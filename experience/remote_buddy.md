# RemoteBuddy：你的 AI 远程同事

**让智能体像人类同事一样工作、学习、协作。**

## 一、核心问题

Coding Agent 正在变强，但它们之间**无法分享经验**。

- 一个 Agent 成功完成复杂任务后，这份「能力」无法被另一个 Agent 直接使用
- 日志、命令序列、skill.md 都不足以让另一个 Agent 可靠地重现成功
- 结果是：每个 Agent 都在重复解决同样的问题，群体学习无法形成

**这个问题随着多 Agent、多模型生态的扩大而日益严重。**

## 二、核心理念

> **让智能体的经验像代码一样被版本化管理、可复现验证、可自由分发。**

我们设计了一套「可验证的经验包」格式，包含：

| 组件                | 作用                          |
| :------------------ | :---------------------------- |
| **tmux 截屏流**     | 记录 Agent 的完整终端操作序列 |
| **Git commit 序列** | 记录每次操作后的文件系统状态  |
| **Docker 环境快照** | 锁定系统环境与依赖            |
| **语义验证脚本**    | 定义什么叫「成功」            |

**关键约束**：分享者必须自己能成功回放。

> 类比：超级马里奥的关卡作者必须自己能通关。

## 三、产品矩阵

### 第 1 层：AgentEcho（基础设施 / 底层协议）

**定位**：智能体经验的「Git + GitHub」

| 组件               | 功能                           |
| :----------------- | :----------------------------- |
| **经验包格式规范** | 定义目录结构、元数据、验证接口 |
| **CLI 工具**       | 录制、回放、验证、分享         |
| **存储后端**       | 支持本地、对象存储、Git        |
| **Harbor 框架**    | 云端并发验证                   |

**开源策略**：核心协议与 CLI 工具开源，降低采用门槛。

### 第 2 层：咨询智能体（应用层 / 经验市场）

**定位**：智能体经验的「按需检索与执行服务」

**核心逻辑**：用户 Agent 遇到问题时，向咨询 Agent 发起查询，获得可验证的经验包直接执行。

**收费模式**：

| 模式           | 说明                |
| :------------- | :------------------ |
| **按次付费**   | $0.01-0.10 / 次     |
| **订阅制**     | 月/年费，无限次咨询 |
| **收入分成**   | 创作者与平台 70/30  |
| **企业许可证** | 私有化部署 + 年费   |

### 第 3 层：RemoteBuddy（用户界面 / 最终产品）

**定位**：与人类并肩工作的虚拟同事

**产品形态**：

- 运行后暴露一个 tmux 界面
- 人类用自然语言（语音/文字）沟通意图
- RemoteBuddy 直接操作鼠标键盘
- 遇到困难可向人类求助，或去咨询智能体获取经验

**核心价值**：

| 问题         | RemoteBuddy 的解法                |
| :----------- | :-------------------------------- |
| **信任问题** | tmux 界面全程可见，人类可实时监督 |
| **能力边界** | 可调用咨询智能体获取外部经验      |
| **协作成本** | 自然语言沟通，像与同事开会        |

## 六、演进路线

### 第一阶段：AgentEcho MVP（0-6 个月）

- 定义经验包格式 v1.0
- 实现 CLI 工具（录制、回放、验证）
- 跑通「录制 → 自回放 → 验证成功」闭环
- 开源核心协议

**成功标准**：3 个外部团队试用，10 个高质量经验包

### 第二阶段：咨询智能体试点（6-12 个月）

- 搭建经验市场后端
- 手工创建 100 个高频领域经验包
- 邀请 5-10 个 Agent 团队作为早期客户
- 测试收费模式

**成功标准**：产生第一笔付费交易，续费率 > 70%

### 第三阶段：RemoteBuddy 原型（12-18 个月）

- 实现自然语言 → tmux 操作的核心闭环
- 集成咨询智能体作为经验来源
- 邀请个人开发者试用

**成功标准**：100 个日活用户，周使用时长 > 5 小时

### 第四阶段：生态扩展（18-24 个月）

- 开放经验包市场，允许第三方创作者上传和售卖
- 支持企业私有化部署
- 与主流 Agent 框架集成

**成功标准**：1000+ 经验包，100+ 付费创作者，年收入 > $1M

## 七、商业逻辑

| 产品层          | 收入来源                      | 目标客户              |
| :-------------- | :---------------------------- | :-------------------- |
| **AgentEcho**   | 企业版授权（私有化部署、SLA） | 大型企业、云厂商      |
| **咨询智能体**  | 按次 / 订阅 / 分成            | Agent 开发者、AI 团队 |
| **RemoteBuddy** | 订阅制（$20-50/月）           | 个人开发者、技术团队  |

**核心护城河**：

1. **网络效应**：越多 Agent 使用，经验包越丰富
2. **可验证性**：自回放约束是质量门禁
3. **跨模型兼容**：不绑定任何特定模型或框架

## 九、风险与对策

| 风险             | 应对策略                              |
| :--------------- | :------------------------------------ |
| **冷启动**       | 手动创建前 100 个经验包，聚焦高频领域 |
| **质量参差**     | 自回放约束 + 社区评分 + 脚本公开审查  |
| **非确定性环境** | Docker + 固定种子 + mock 外部 API     |
| **用户信任不足** | 透明操作界面 + 可独立验证的回放       |
| **大公司竞争**   | 先以开源协议建立事实标准              |
